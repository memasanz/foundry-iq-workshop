# Lab 13 - A simple C# hosted agent with Microsoft Agent Framework

[Optional C# notebook](../../c-sharp-notebooks/13-hosted-agent.ipynb) | [Python lab](../../python-notebooks/13-hosted-agent.ipynb)

The supported **.NET 10 console app** follows Python lab 13's write -> zip -> remote build -> wait -> Responses API flow. The deployed agent is also **C#**, with one local function tool, not Python generated by a C# launcher. The launcher uses only `HttpClient` and .NET libraries; Foundry restores the generated agent's NuGet packages. No Python, Docker, ACR, `azd`, Search, Blob ingestion, Web IQ key, toolbox or app registration is required.

Run from the repository root:

```powershell
dotnet run --project .\c-sharp-console-apps\13-hosted-agent -- --help
dotnet run --project .\c-sharp-console-apps\13-hosted-agent -- run
```

**`run` creates a version and makes two model-backed example calls.** Hosted compute, model inference and sessions can incur charges; use synthetic questions. `run` does not delete resources.

## Prerequisites and settings

Use an existing Foundry project and chat deployment with hosted **.NET code deployment / remote build** availability. Region/feature support can differ from Python hosting; an available project or a successful launcher build does not prove hosted runtime support.

- Install the .NET 10 SDK and Azure CLI. Sign in as your user with `az login --tenant <AZURE_TENANT_ID>`.
- Your workshop user needs **Foundry Owner on the parent Foundry resource**, covering authoring and invocation. Project-only Foundry User is not the full workshop authoring setup.
- The deployed agent identity needs model inference access in the existing project. The facilitator must ensure that access is provided; this lab does not assign Azure roles.
- No Search roles, SharePoint licenses, tenant administrator consent or custom broker app are required.

Required settings: `WORKSHOP_PREFIX`, `AZURE_TENANT_ID`, `AZURE_AI_PROJECT_ENDPOINT`, `AZURE_AI_MODEL_DEPLOYMENT_NAME`. Load the root `.env`, then `.env.azure`; both override environment values and `.env.azure` wins. The prefix must be 3-20 lowercase letters/digits, starting with a letter; tenant ID must be a GUID. The endpoint check accepts public-cloud `https://<account>.services.ai.azure.com/api/projects/<project>` URLs only, without credentials, a query or fragment. Model names are deployment names, not model-family names.

The Azure agent keeps Python13's name **`<prefix>-hosted-agent`**. Publishing from either language creates another immutable version under that name; use a different prefix if both agents must coexist independently. This C# lab writes to **`<prefix>-csharp-hosted-agent`**, leaving Python's `<prefix>-hosted-agent\main.py` and `requirements.txt` untouched. Both folders match the existing generated-folder Git ignore rule. Prefixes prevent collisions, not enforce authorization or data isolation.

## Run one step at a time

| Command | What it does | Result / prerequisites |
|---|---|---|
| `write-agent` | Write `WorkshopAgent.csproj`, `Program.cs` and `WorkshopTips.cs` in your generated C# folder. | Local source only, no token request or Azure call. **Overwrites these three files**; use `package` after editing them, not `write-agent`. |
| `package` | Zip exactly those existing three files, with filenames at the archive root. | Creates/replaces `agent.zip`; requires `write-agent` once. Does not modify your code, install packages or include `bin`, `obj`, `.env`, tokens or other files. |
| `deploy` | Validate the existing archive, calculate its SHA-256 and upload it with the hosted definition. | Creates one immutable version. Requires `package`; does not rewrite/package files, wait for the build or ask a question. Prints version ID and status. |
| `status [version]` | Read the specified version or the existing agent's latest version. | Read-only provisioning status; no deployment, polling or model call. |
| `wait [version]` | Select the existing latest version if no ID is supplied, then poll that fixed version every 15 seconds for up to 15 minutes. | Stops on active, failed/deleting/deleted or timeout. Does not create a version or invoke the agent. Supply the ID printed by `deploy` to monitor that exact deployment. |
| `invoke [question]` | Send one Responses request to the hosted agent endpoint; print answer and returned session ID. | Requires an existing runnable agent. Defaults to the Foundry IQ tip question. No `model` argument, user follow-up, retries or setup writes. |
| `invoke-tool` | Ask once for the `indexer` tip and print output item types. | Helps inspect function-tool use; a plausible/exact answer or message-only output does not itself prove the function ran. |
| `run` | Write, package, deploy, wait for the returned version, then invoke both example questions. | Complete flow; no local step cache required. Overwrites generated source and creates a new version on each run. |
| `cleanup --confirm` | Check the existing latest version's name, hosted kind and workshop/prefix metadata, then delete the agent and versions. | Deletes only `<prefix>-hosted-agent`; preserves shared project/model and local files. Active sessions can cause HTTP 409; **never force-deletes sessions**. |
| `help`, `--help`, `-h` | Explain commands without reading files/configuration, acquiring credentials or contacting services. | Works offline, without settings or Azure CLI. No arguments also displays help. |

```powershell
dotnet run --project .\c-sharp-console-apps\13-hosted-agent -- write-agent
# Optional local compile check of the generated agent; requires NuGet access, not Azure sign-in.
dotnet build .\alice01-csharp-hosted-agent\WorkshopAgent.csproj
dotnet run --project .\c-sharp-console-apps\13-hosted-agent -- package
dotnet run --project .\c-sharp-console-apps\13-hosted-agent -- deploy
dotnet run --project .\c-sharp-console-apps\13-hosted-agent -- status
dotnet run --project .\c-sharp-console-apps\13-hosted-agent -- wait
# Or: wait "<version printed by deploy>"
dotnet run --project .\c-sharp-console-apps\13-hosted-agent -- invoke
dotnet run --project .\c-sharp-console-apps\13-hosted-agent -- invoke "Give me a tip about web iq."
dotnet run --project .\c-sharp-console-apps\13-hosted-agent -- invoke-tool
```

Replace `alice01` with your actual prefix in the local build example. Console and notebook steps work independently against existing resources; restarting the console/kernel requires no cache recovery. `status` and `wait` can select the latest existing version with metadata reads. Invocation uses the **agent name's endpoint routing**, as Python13 does; a version ID used for polling does not pin the Responses call to that version. Check the Foundry endpoint/version routing if it was customized outside this lab.

## Understand the generated agent

```text
Your C# notebook / launcher -- code zip + definition --> Foundry remote build
                                                        |
                         Program.cs: Agent Framework + function tool + Responses host
                                                        |
Your signed-in user -- hosted Responses endpoint --> your C# code -- agent identity --> model
```

`WorkshopTips.Get(string topic)` returns the same three one-line tips as Python13, using case-insensitive topic lookup and an honest fallback. It performs no web query or Search retrieval. `AIFunctionFactory.Create(..., "get_workshop_tip", description)` exposes that normal C# function to the agent's model.

`AIProjectClient(..., new DefaultAzureCredential()).AsAIAgent(...)` combines the existing model, instructions and tool. The **hosted runtime** receives `FOUNDRY_PROJECT_ENDPOINT` and identity information from the platform; the deployment supplies only `AZURE_AI_MODEL_DEPLOYMENT_NAME`. Do not add reserved `FOUNDRY_*` values or user tokens to the deployment environment.

`AgentHost.CreateBuilder`, `AddFoundryResponses` and `MapFoundryResponses` provide the C# equivalent of Python's `ResponsesHostServer(agent).run()`. The generated project follows the official [C# hosted local-tools sample](https://github.com/microsoft-foundry/foundry-samples/tree/main/samples/csharp/hosted-agents/agent-framework/local-tools), with its concrete hosting/projects package versions rather than floating prerelease dependencies. See [Foundry hosting with Agent Framework](https://learn.microsoft.com/agent-framework/hosting/foundry-hosted-agent?pivots=programming-language-csharp).

## What gets uploaded?

`POST <project>/agents/<prefix>-hosted-agent/versions?api-version=v1` uses multipart form data:

- `metadata`: JSON containing the hosted definition, description and `workshop=iq` / `attendee=<prefix>` metadata.
- `code`: the existing `agent.zip`, `application/zip`.
- `x-ms-code-zip-sha256`: digest of that exact archive for integrity/change detection.

| Definition setting | Value / meaning |
|---|---|
| `kind` | `hosted`: run your own application, not a prompt-agent definition. |
| `runtime` | `dotnet_10`, replacing Python13's `python_3_13`. |
| `entry_point` | `["dotnet", "WorkshopAgent.dll"]`, matching the generated assembly name. |
| `dependency_resolution` | `remote_build`: Foundry restores/builds the C# project. |
| `protocol_versions` | Responses `2.0.0`. |
| `cpu` / `memory` | `0.5` / `1Gi`, matching Python13. |
| `environment_variables` | Existing model deployment name only; no secrets. |

REST wire shapes, hosted endpoint URL and `Foundry-Features` header match the installed Python `azure-ai-projects` code path. Azure CLI requests the `https://ai.azure.com` resource, equivalent to the SDK scope `https://ai.azure.com/.default`. Authoring/invocation uses **your credential**; model inference inside Foundry uses the **agent runtime credential**. There is no APIM broker/OBO exchange here.

## Wait, inspect and change the tool

**`active` is provisioning readiness, not runtime readiness.** A successful `invoke` confirms that the application starts and answers; HTTP 424 can still indicate startup/session problems after an active build. Inspect Foundry build/runtime diagnostics for package restore errors, entry-point mistakes or model permissions. An unavailable hosted .NET runtime is a deployment limitation, not a reason to quietly deploy Python instead.

Each Responses request contains `input` and `store=false`, without `model`, and is made once. The first call can create a hosted session and return `agent_session_id`. No session selector or `previous_response_id` is supplied for either example; this lab does not reuse a conversation or persist IDs, prompts, answers or tokens locally. `store=false` is not a promise of zero platform telemetry/session retention.

Inspect output item types and runtime tool logs. To make a convincing tool experiment, change a tip to a unique **synthetic** sentence in generated `WorkshopTips.cs`, run `package`, `deploy`, `wait`, then `invoke-tool`. Do not rerun `write-agent` or `run`, which overwrite the edit. The new version is an immutable snapshot; old sessions/endpoint routes might still refer to an older version. A model can know the original indexer definition without calling the tool, so answer wording alone is not conclusive.

HTTP failures print status, UTC Date, available request/correlation IDs and a bounded bearer-redacted body before exiting nonzero. Invalid JSON, partial/incomplete/failed Responses results, missing output text, provisioning failures and timeouts are not treated as successful answers. No automatic billable retries or hidden deployments run. Diagnostics may still contain prompt/answer content; clear notebook outputs before sharing.

## Cleanup

```powershell
dotnet run --project .\c-sharp-console-apps\13-hosted-agent -- cleanup --confirm
```

Cleanup first verifies the latest version is your named **hosted workshop agent**, then deletes only that agent. There is no `force=true`: if active sessions block deletion, close them through Foundry and rerun explicitly. It does not delete another prefix, the Foundry project, chat model or generated local folder. Reusing the same prefix from Python13 and C#13 also means cleanup removes both languages' versions under that one agent name.
