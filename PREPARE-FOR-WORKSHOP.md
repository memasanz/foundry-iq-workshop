Prepare the test site, documents and access for your selected SharePoint path before running 09. The knowledge-base lab is not notebook 06; notebook 10 builds on 09, and notebook 12 combines 09's Blob knowledge source with 11's hosted-agent pattern.

## Prepare for the workshop

**Suggested deployment region: East US (`eastus`).** Central US (`centralus`) does not currently support Content Understanding, and East US 2 (`eastus2`) is currently capacity-constrained for new AI Search deployments. East US supports both services, so we recommend deploying Foundry, AI Search and Storage together there; Web IQ stays global. APIM is not provisioned by Bicep; notebook 10 uses an existing gateway, which can remain in its current region. Verify regional capacity and model quota before class. Changing this default does not move existing resources.

### What changed with notebook 05?

**Participants need the same Search and Blob roles as notebook 04.** The extra requirement belongs to **Azure AI Search's system-assigned managed identity**: it needs **Cognitive Services User on the parent Foundry resource** for Content Understanding. An embedding-only Cognitive Services OpenAI User grant is not the documented keyless Content Understanding attachment permission.

The current Bicep templates already grant Cognitive Services User to Search's identity, so a deployment using them needs no additional participant grant for notebook 05. For an existing/custom deployment, verify this service-to-service grant and the supported Foundry region. The stable-API exercise needs no extra chat model, app registration or client secret. PDF analysis and embeddings are billable; permission to call them is not a spending limit.

The original push-ingestion lab is now **06**, SharePoint labs are **07-08**, and the remaining labs are **09-13**. Choose the labs you will run before requesting tenant consent, licenses or gateway changes.

### Final checks before participants arrive

- Activate required PIM roles, sign in to the workshop tenant, and allow time for new role assignments to propagate. Keep subscription deployment/role-assignment privileges with the facilitator; attendees do not need subscription Owner.
- Test an authenticated upload into the configured Blob container. **Container-scoped Blob Data Contributor permits direct uploads**; Azure portal navigation may additionally require Reader on the Storage account. Network restrictions can still block an authorized caller.
- Verify the generated `.env.azure` points at the current deployment. Restart notebook kernels after changing deployments so stale endpoints do not look like permission failures. A DNS failure is not an RBAC error; HTTPS port 443 is not an HTTP error code.
- Run a real PDF ingestion for notebook 05 and inspect indexer errors, page ranges and embeddings. Creating a skillset successfully does not prove downstream service access. Obtain approved account-specific networking exceptions where required; never bypass organization policies.
- Use trusted attendees and non-sensitive documents. Shared Search/Blob roles are not per-attendee isolation, and sufficiently privileged Foundry members can access shared connection secrets. Verify both allowed and denied SharePoint cases before class.
